1 — Ordinary BTHome advertising
Packet id and battery, as before, plus a declaration listing the object types this device accepts writes for — here three lights.
40 00 f0 01 64 ff 1e 1e 1e
ff 1e 1e 1e → entries 1, 2, 3, served on 2FAA0001…0003. Last in the service data, so any BTHome receiver skips it; nothing else changes.

2 — Discovered, no configuration
The declaration says what to offer. Entities appear beside the sensors the core BTHome integration already made, on one device card.
4 — Applies it, and acknowledges
The write response says the bytes arrived; the second light going out says what they did. The advertising is unchanged but for the packet id — a written value is never advertised.

3 — Writes one object, to that entry's characteristic
Connect, write with response, disconnect. Entry 2 is 2FAA0002, and nothing else on the device is touched. The object ID is redundant given the characteristic, and that is the point: it catches a receiver writing against a layout the device no longer has.
→ 2FAA0002   1e 00
